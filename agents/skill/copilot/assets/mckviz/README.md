# mckviz, in pieces (Microsoft 365 Copilot edition)

`scripts/mck_setup.py` loads `mckviz` (v{{version}}) in a sandbox that can't install packages or reach the internet. Run it once at the start of the first chart:

```python
import runpy
setup = runpy.run_path("<skill folder>/scripts/mck_setup.py", run_name="__main__")
mv, C, SKILL_DIR = setup["mv"], setup["C"], setup["SKILL_DIR"]
```

Copilot skills accept only some file types, and only script types (`.py`, `.js`, `.sh`, ...) under `scripts/`, so the package ships in pieces that the script puts back together in a temp folder:

| In the skill | Becomes |
|---|---|
| `scripts/mckviz_src/*.py` | the package code |
| `assets/mckviz/*.json` | the tokens and the Plotly template, as they are |
| `assets/mckviz/mckviz.mplstyle.txt`, `VERSION.txt` | `mckviz.mplstyle`, `VERSION` |
| `assets/geodata/` | `mckviz/geodata/` (US states, a county subset, world countries) |
| `assets/fonts/*.ttf.b64.txt` | the Libre Franklin TTFs (base64-encoded here; SIL Open Font License in `assets/fonts/OFL.txt`) |

Everything is generated by `tools/build_skill.py` from the data-viz-guide repo ({{repo_url}}); edit the source there, not here.
