# Roadmap

Last updated: 2026-10-18. The kit is the **Data Viz Starter Kit · McKesson Edition**, version 1.1.0 (`VERSION`, `CHANGELOG.md`); how we name and describe it is in [`docs/positioning.md`](docs/positioning.md). This page has two parts: **What's next** (for anyone) and the **Working log** below it (for whoever resumes work on the kit, person or agent; read it before you start).

## What's next

The owner's goal from here: turn the kit from a "could we do this?" experiment into something cohesive enough to share with any McKesson team, while Workforce Innovation stays the first user and the examples stay workforce data. The repo is the **engine** (tokens, rules, lint, `mckviz`, build, skill); the guide, the Office kit and the agent playbook are the first **product** on it, and others can follow.

**In order:**
1. **Finish-line items a stranger will notice** (done 2026-10-18, except the video): `LICENSE` (MIT, McKesson Corporation) and the license line in `python/pyproject.toml`; maintainer and contact (Ashley McCown, Workforce Innovation, GitHub issues) in pyproject, the READMEs and START-HERE's "questions" line; this file split into a short public "what's next" and the working log. Still to do: drop "a work in progress" from the video's closing card when the video ships.
2. **The explainer video** (done 2026-10-18, except the upload): the source is the tracked video kit in [`video/`](video/README.md) (the engine, the characters, the voice pipeline, this video's scenes and final voice, a template for the next video; about 8 MB), and [`demo/`](demo/README.md) presents the kit on one screen with the video and the outputs it shows. Still to do by the owner: attach `data-viz-kit-explainer-video.mp4` (147 MB, over GitHub's file limit, so never in git) to the next GitHub Release, then fill in its link in `demo/README.md` (there is no SharePoint copy); and drop "a work in progress" from the closing card when the video is re-exported.
3. **The agent door for non-coders:** "paste a table, ask a question, get five on-brand options with computed headlines" (the video's "coming soon"). The portable skill was tested in Claude.ai on 2026-10-18 (Opus 5.5, a five-options request and one chart turned into a PowerPoint slide): the charts came out to house rules, but `mckviz` could not be installed from the sandbox (the repo is private), so `mv.lint` never ran, the font had to be fetched from npm, one run invented a source line, and Claude.ai's own pptx skill built a native chart the skill had called impossible. The same day closed those gaps: the skill zip now carries the `mckviz` wheel, the fonts and the Office template (`python tools/build_skill.py --zip`, 1.8 MB, installs offline), a pptxgenjs theme generated from the tokens with a native-chart recipe, the missing-metadata and label-on-benchmark rules, and three eval cases that are not the bundled sample (`python/tests/eval_cases/`). A second run the same day on a fresh dataset (`python/tests/eval_cases/runs/2026-10-18-claude-ai-opus-5.5.md`) passed every check: wheel install, lint, suppression, placeholder source, native slides; its ten friction points fixed word-safe wrapping, `mv.dumbbell(focus=)`, the floored-waterfall lint note and stacked pptxgenjs presets. Next: run the other three eval cases, test in Copilot, then decide whether the flow is a skill, a Claude Code plugin or a small app on `mckviz`. What remains is listed under Productizing in the working log.
**Parked idea (2026-10-18): a McKesson AI analyst.** People the owner knows built [ai-analyst](https://github.com/ai-analyst-lab/ai-analyst) (MIT): an open-source AI data analyst inside Claude Code that frames the decision, profiles data, pairs every number with a comparison, traces findings to rows, keeps a `.knowledge/` memory with a corrections log, has an eval harness and exports to Docs, Slides, Notion and PDF. Its chart layer is a thin YAML theme that cannot express our rules. The plan when we get to it: clone it and build our own analyst, with this kit's data-viz and storytelling structure on top. The split is **exploratory vs. explanatory**: their analyst explores and finds (profiling, comparisons, provenance); our kit explains and persuades (question first, chart choice, headline, brand, QA, native Office). Worth borrowing before then: the corrections log, "every number gets a comparison", decision framing ahead of the question, frozen eval cases for the chart skill (the answer to "lint passes, eyes fail"), and export routing.

4. A fresh end-to-end read of the guide against `docs/positioning.md` (audience wording, "we", the three ways in), then the open items below.
