# Changelog

All notable changes to the Data Viz Starter Kit, McKesson Edition (the guide, the themes, the `mckviz` package and the agent assets). The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/): a major version changes a rule or breaks code that uses `mckviz`, a minor version adds things, a patch fixes them.

The version lives in one place, the `VERSION` file at the repo root. `tokens/build.py` copies it into the Python package, and the guide cover, the agent rules, the portable skill and the release bundle read it from there. Releases are tagged `v<version>` (for example `v1.1.0`); `pip install` and the release bundle refer to those tags.

### Added
- **Errors that name the fix** (2026-11-02, branch `feat/code-first`). Agents guessed `C.grey` and `C.muted` and drew the headline with `fig.text`, so the skill carried the list of color roles and a warning. Now a wrong name on `mv.colors` raises an error that lists the roles (context is the grey, focus the McKesson Blue, accent the one navy exception, ...), and lint's "no headline" error names `mv.titles` and says a `fig.text` headline isn't one. The skill's line shrinks to "copy the snippet; the frame comes from `mv.titles` and `mv.source`". (`mv.highlight` keeps no cap of its own: the scatter spec names up to five focus points, so the two-highlight limit stays in the bar-style builders.)
- **Picture slides fill the chart area, and say when a figure won't** (2026-11-02, branch `feat/code-first`). In the 2026-10-27 core run a Sankey picture slide sat small: the agent built the figure at the cookbook's 10 × 5.6 in, a 1.8 : 1 shape on a 2.8 : 1 chart area, so it filled 57% of the width. `picture_slide` still places a figure as its builder laid it out (redrawing it squeezes labels), but now also enlarges a smaller one to fill the area (text 1.5× at most), and warns when the picture leaves part of the area empty or had to be scaled much, naming `office.picture_figure()` as the fix, so the next build is right.
- **Working files stay out of Copilot's `/mnt/data`** (2026-11-02, branch `feat/code-first`). Every write there becomes another copy in the user's OneDrive, and an options page's HTML and PDF came back as numbered copies. `mv.office.save` already refused it; now `mv.save`, `mv.options_page` and `mv.page_pdf` do too, through `mv.working_path`, whose error says what to do instead: save to `/tmp`, check it (`mv.look`), then `mv.deliver` hands it over once. The sandbox starts in `/mnt/data`, so a bare `"chart.png"` is caught as well. Outside Copilot (no `/mnt/data`) nothing changes. The skill's OneDrive paragraph is down to the one habit that matters.
- **`mv.bar`, the ranking bar in one call** (2026-11-02, branch `feat/code-first`). The sorted bar is the start chart most of the time, yet it was the one common chart without a builder: the tree's helper was `ax.barh + mv.highlight + mv.label_bars`, and in the 2026-10-27 core run a "lagging adoption" PNG put its two blue bars at the bottom while the slide put them on top. `mv.bar(ax, labels, values, focus=, accent=, uniform=, benchmark=, benchmark_label=, fmt=, sort=)` draws the bar spec (2 : 1 bars, values at the bar ends, bold for the highlighted bars, a labelled dashed benchmark with white backings where a label meets it, a zero baseline, no value axis, at most two highlighted) and sorts with the story on top through `mv.story_order`, which `mv.office.bar_slide` now shares, so a chart and its slide agree. The tree names `mv.bar` for four sorted-bar leaves, the bar cookbook page and the guide's Magnitude page build with it, and the skill's builder index is now one line (`mv.suggest` and the decision tree name every builder). `__all__` lists every builder, the table, `suggest` and the options page.
- **`ROADMAP.md` split by purpose** (2026-10-27). It had become a session-by-session log. Now `ROADMAP.md` is one screen (Now, Next, Later, Decisions) rewritten each session; the history moved word for word to `docs/worklog.md` (newest first, one dated entry per session); the build, release and extend steps and the working notes moved to `docs/maintaining.md`. `AGENTS.md` says how to keep them.
- **Slide fixes from the core regression run** (2026-10-27, branch `feat/office-native-slides`). `bar_slide` puts the story on top: largest first, or smallest first when the highlighted bars are the small ones (a "lagging" headline put its two blue bars at the bottom); `sort="descending"` / `"ascending"` force it. `picture_slide` no longer redraws the figure at the slide's size, which squeezed a Sankey's columns until labels collided; it places the figure as built, and `office.picture_figure()` starts a figure at the chart area's size with the plot filling it, so builders that measure their labels (`mv.sankey`) lay out for the space they get. `mv.clear_delivered` covers every delivered file, not only Office files (an options page's HTML and PDF came back as numbered copies too), and `mv.deliver`'s "same file" check looks inside a chart's embedded workbook, whose own dates made a rebuilt deck look changed.
- **`mv.deliver` and `mv.look`: files reach the user once** (2026-10-27, branch `feat/office-native-slides`). In Copilot every write to `/mnt/data`, even after a delete, becomes another copy in the user's OneDrive, and two runs on 2026-10-27 left extra copies anyway: the agent copied a check render there to look at it, and replaced a delivered deck with its own `rm` and `cp` (four extra decks). `mv.deliver(*paths)` (any file; `mv.office.deliver` now calls it) copies each finished file from `/tmp` once; delivering the same file again does nothing, even when it was rebuilt (build dates in Office and PDF files are ignored), and a second version of a deliverable already handed over in the chat (a changed file, or the same name with `_v2`) is refused unless `revision=` says what the user asked to change: a third run delivered `_v2` and `_v3` decks while fixing a warning. A probe in Copilot (2026-10-27) then found where most copies came from: every later code run uploads the files left in `/mnt/data` again, and an Office file comes back as "name 1.pptx", "name 2.pptx", ... because OneDrive changes it after the first upload (a delivered deck grew from 579 to 588 KB). Removing it from `/mnt/data` keeps the OneDrive file and its link. So `mv.clear_delivered()`, which `scripts/mck_setup.py` runs at the start of every script, takes the Office files delivered by an earlier script out of `/mnt/data`, and delivering one of them again stays a no-op. `mv.look(png)` shows a render in the notebook output so the agent can check it without writing it to `/mnt/data`. `SKILL.md`, `native-formats.md` and `options.md` now build and check in `/tmp` and deliver with `mv.deliver`, never `cp`, `mv` or `rm` in `/mnt/data`.

The first Copilot test of a native slide (2026-10-26) built it ad hoc with python-pptx and got four things wrong: a column chart sorted ascending, gridlines left on, the plot pushed right, the benchmark drawn between two columns. `mckviz.office` builds slides on the McKesson branded template (`office/brand/`, written to `python/mckviz/template.pptx` by `office/build_office.py`), with the headline as the slide title at the master's 34 pt when it fits on one line, else 28 or 26 pt on two (an error over two). `bar_slide` draws a ranking (sorted from the top, no gridlines or value axis, the plot right after the labels, end labels that follow Edit Data, the benchmark as a dashed line across all bars with any label on it moved inside). `column_slide` draws periods or stages as columns in their given order, `line_slide` draws `mv.line`'s spec as a native line chart (end labels nudged apart, light gridlines, a target line, the forecast dashed after a divider), and `stack_slide`, `waterfall_slide` and `dumbbell_slide` take the arguments of `mv.hstack`, `mv.waterfall` and `mv.dumbbell` (segment names over the top bar instead of a legend; a stacked-column bridge with a floor and break marks; an XY dumbbell with a key). The starter deck's column, stack, waterfall and dumbbell slides now use them. `picture_slide` puts any other mckviz figure on the slide as a picture, taking its own headline, subtitle and source off so each appears once. `save` refuses Copilot's `/mnt/data`, and `deliver` copies the checked deck there once, because every write there (a validator's rewrite and its `.orig` backup included) became another copy in the user's OneDrive. The skill's `native-formats.md` routes every McKesson slide through `mv.office`, never PptxGenJS. `python/tests/test_office.py` covers it.
- **Lint catches hand-built line charts** (2026-10-26, branch `feat/share-and-helpers`). In Copilot the agent drew a line chart by hand instead of with `mv.line`, and it read as heavy: markers on every point, thick lines, a y-axis title, a grey target line whose label sat on the data, and a context label in the line's grey. `mv.lint` now warns on each (`line-markers`, `reference-line`, `axis-title`, `text-contrast`) and names `mv.line` as the fix, so the QA step sends the agent back to the builder. `mv.line` places its target label at whichever end and side of the line is furthest from the data.
- **`mv.share_bar`, `mv.line` and `mv.dot_plot`, and a calmer `mv.strip`** (2026-10-26, branch `feat/share-and-helpers`). `mv.share_bar` answers "what share of each group is beyond a threshold?" from one row per person (a new question in the tree, where it is the start chart and the strip plot is the Option). `mv.line` draws lines over time with grey context, a blue focus, de-collided end labels kept inside the plot, a target, a shaded event and a dashed forecast with a scenario band; it replaces a 54-line recipe. `mv.dot_plot` draws one value per row far from zero, with a named benchmark. `mv.strip` now boxes only the focus group by default (`box="focus"`), with median ticks and fainter dots for the rest. The cookbook pages, the tree, the skill's builder index and AGENTS.md use them.
- **Skill architecture: a 14,000-character budget and task guides** (2026-10-26, branch `feat/chart-helpers`). The Copilot `SKILL.md` had reached 19,800 of its 20,000-character limit, and about 6,000 of those were needed only for some requests. It is now 12,900: the options-page recipe, chart review and the native Excel, PowerPoint, Power BI, HTML and R steps moved word for word into task guides (`agents/skill/references/options.md`, `review.md`, `native-formats.md`, filled per edition into `references/`), each behind a one-line pointer in a new "Task guides" list near the top of `SKILL.md`. Chart review now ships in every edition, not only Copilot's. `tools/build_skill.py` fails when the Copilot `SKILL.md` goes over `SKILL_BUDGET` (14,000), and `AGENTS.md` describes the four layers (code, `SKILL.md`, task guides, reference docs) and what goes in each.
- **`mv.sankey` and `mv.strip`, two more charts in one call** (2026-10-26, branch `feat/chart-helpers`). Agents skip charts that take many lines by hand. `mv.sankey(ax, flows, focus=, worse=, accent=, stages=)` draws the Sankey spec in matplotlib: curved semi-transparent bands on one scale, thin navy nodes with name and total, pass-through labels above their nodes, grey context with the headline's flows in color, and a refusal for flows under 10. It replaces the Plotly-only route, whose PNG export needs Chrome. `mv.strip(ax, df, group, value, ...)` draws the distribution spec: dots per person, a box and median per group, sorted by median, the zone and reference line named in place, share and n at each row end, groups under 10 suppressed; `dots=False` gives box plots with 10th–90th percentile whiskers. Both cookbook pages now build with them, and the decision tree names them as helpers.
- **`mv.page_pdf`, the options page as a PDF** (2026-10-26). In Copilot, a linked .html opens in the OneDrive viewer, where "Open in app" fails until the file is downloaded. `mv.page_pdf(path)` prints the page to a PDF beside it with weasyprint (in Copilot's sandbox; it returns None where weasyprint can't load), so the skill now hands back the PDF to read and forward, and the .html, with a one-line "download it first", for the Download and Copy buttons.
- **Color patterns 2 and 3 in stacks and in the decision tree; footnotes that wrap** (2026-10-26, branch `feat/chart-decision-tree`). The first Copilot test of the options page showed two problems. First, Pattern 3 (focus + accent) was never chosen: no question in the tree led to it. Six questions now switch to it when the headline names a group and one member stands out, and the skill says to use it for any "led by" headline. Second, the charts came out at odd sizes: a footnote was one long line, so the tight bounding box widened the image to fit it and the chart sat small inside. `mv.layout` now wraps the footnote and source line to the width of the plot and headline; `mv.source` replaces an earlier source line instead of adding a second; and `mv.lint` warns (`off-canvas`) when other text runs well past the figure edge. `mv.hstack` takes the three patterns that `mv.highlight` already did: `story=` (one segment or a group of two) in blue, `accent=` for the navy standout on the baseline, and `uniform=True` for light blues instead of greys.
- **`mv.table`, the blended table in one call** (2026-10-26, branch `feat/chart-decision-tree`). Agents rarely used tables because the scorecard recipe was 68 lines by hand. `mv.table(ax, df, label, [mv.Col(...)])` draws the tables.md spec: inline bars, at most two heat columns on their own scales (blue; orange when darker means worse; diverging around a benchmark), a change column with only the unfavorable direction in orange, bold focus rows (two at most), a navy-ruled total weighted by a count column, n<10 suppression, column widths fitted to the content and the figure height fitted to the rows. It returns the footnote text. The tables.md snippet now uses it; the decision tree gains an "exact figures" question (a blended table) for categories and for before/after pairs, the scorecard question starts with a blended table, and options pages of four or more include one as the reference view. `python/tests/test_table.py` covers it.
- **The chart decision tree and `mv.suggest`** (2026-10-26, branch `feat/chart-decision-tree`). Agents defaulted to the safe first choices (a sorted bar, a 100% stacked bar in greys) because the chooser listed one first choice per question type and the richer charts took 60–90 lines to build by hand. `tokens/chooser.json` is now the single source for a tree in the spirit of data-to-viz.com: 1. what is in the data (13 shapes: one number, people-level rows, categories × one measure, parts of a whole, a bridge, a pair per category, categories × several measures, two category sets, time, flows, places, plans, overlapping sets); 2. the question; 3. a chart to start with and the charts to go further with, each behind a condition the data can be tested for (a count column that varies 5-fold or more, values bunched far from zero, more than 12 categories, ordered parts, more than 4 series, two units over time); then the color pattern from the guide's Fundamentals (Focus, Uniform + accent, Focus + accent, Story segment + greys, Categorical, Sequential, Diverging, Steps, Status). `mv.suggest(df)` reads a table into the tree and reports the column roles, the shapes, each question's start chart, the go-further charts whose conditions hold (with the evidence), the color pattern and what the data can't support. `tools/build_chooser.py` (run by `tokens/build.py`) checks the tree against the code and the cookbook, copies it into the package and writes `docs/chart-decision-tree.md`, which the skill carries. The skill's step 2 now walks the tree, the chart brief gains Path and Color lines, and options requests must vary the chart types. `python/tests/test_chooser.py` places all the sample datasets.
- **The options page, `mv.options_page`** (2026-10-26), for a group that sees the same data differently. It puts several views on one self-contained HTML page: what the data shows, an at-a-glance table of each option's headline, then each option with the question it answers, how to read it, its strength and its trade-off, plus Download and Copy buttons for PowerPoint, definitions and data notes, and a source line. The charts (PNG), Libre Franklin and styles from the tokens are inside the file, so it opens offline and can be emailed or posted; "Save as PDF" prints one option per landscape page. Optional `recommendation=` and `lead=` mark a suggested lead, and `label=` a sensitivity line. Modeled on a page built by hand in a coding-agent session for a leadership group deciding how to show AI-potential data. It renders through `canvas.print_figure`, which skips sandboxes that patch `savefig` (Copilot's writes a JSON chart spec beside every PNG). The skill gains "The options page" section; `examples/python/options_page.py` builds a four-option page from `automation_exposure.csv`; `python/tests/test_page.py` covers it.
- **Microsoft 365 Copilot edition of the `mck-chart` skill** (2026-10-19), for a chart agent built in Agent Builder that a team opens from Copilot chat. Agent Builder takes a skill as a `.zip` with `SKILL.md` at its root, carries only some file types and runs scripts in a sandbox with no pip and no network, so the Claude skill zip can't be uploaded as it is. `python tools/build_skill.py --copilot` writes `dist/skills/mck-chart-copilot.zip` (0.9 MB) from the same template and references. `mckviz` ships as source, with `mckviz.mplstyle`, `VERSION` and the five Libre Franklin weights in use stored as text, and `scripts/mck_setup.py` puts the package back together in a temp folder and applies the style, with no install. The Copilot `SKILL.md` adds a "Reviewing a chart" section and Copilot-specific build, hand-back and setup steps (a PNG in chat, native Office steps for decks, Power BI DAX). The build fails if the edition breaks an Agent Builder limit (file types, depth, file count and size, instructions under 20,000 characters). `docs/copilot-agent-setup.md` covers setting up the agent: instructions to paste, conversation starters, capabilities, what to test before sharing. The release bundle carries both (`agents/mck-chart-copilot-skill.zip`, `agents/copilot-agent-setup.md`).
